### 4.1 冒烟日志暴露的新 bug（已修复）

服务器日志出现 `KV budget 1.63 GiB → 1 blocks (cap 1)`——预算够 ~800 块
却被 cap 到 1 块。根因：

`LLMEngine.__init__` 只在 draft_model 分支调用 `engine_cfg.validate()`，
**纯 LLM 主路径（生产入口）从不调用** → `runtime_max_model_len` 保持
dataclass 默认 **0**，后果链：

| 受害点 | 后果 |
|---|---|
| `_profile_num_blocks` 的 `max_useful` | `(max_num_seqs×0+63)//64+1 = 1` → KV 池 cap 1 块，并发尽毁 |
| `_prewarm_rope(model, 0)` | cos/sin 仅 1024 位置；位置 >1024 的 eager 前向越界读 |
| `CudaGraphRunner.max_bt` | `0//64+2 = 2` 列 block 表；长序列 decode 越界 |

（e2e/图验证此前未暴露：位置均 <64、或显式传了 num_blocks。）

修复（2 处代码 + 1 个回归测试）：
1. `llm_engine.py`：`validate()` 无条件执行（移出 draft 分支）
2. `llm.py`：`prefill_sum_seqlen_k = max(默认, max_model_len)`（真实模型
   163840 > 默认 32768，否则 validate 交叉断言拒载）
3. 新增 `tests/engine/test_engine_validate.py`：断言无 draft 主路径
   `runtime == max_model_len+1`、`num_blocks > 1`、rope 预热覆盖到位；
   draft 路径 `runtime == max+K+1` 不受影响

验证：`tests/engine` **16 passed**（原 14 + 新 2），组合
`model+triton_ops+engine` 全绿无失败标记。
