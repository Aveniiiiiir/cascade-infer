## 3. 灰度步骤

1. **冻结**：只使用通过验收的 commit；不直接部署 master 最新提交。
2. **单实例**：bf16、`MAX_LEN=4096`、`MAX_SEQS=24`、32GB 卡，不默认开 n-gram/FP8。
3. **内网**：应用只监听 `127.0.0.1:8000`；业务通过 nginx `8080` 访问。
4. **密钥**：真实 API key 写在实例 root-only 环境文件，不提交仓库、不写公开文档。
5. **反代**：启用安全响应头、请求体 10MB 上限、连接/请求限流、SSE `proxy_buffering off`。
6. **守护**：容器用 supervisor；标准主机用 systemd。健康检查失败触发运维告警。
7. **灰度**：先内部 smoke → 1% 内部真实请求 → 5% 观察 24–48h → 逐级放量。
8. **指标**：请求量、5xx/判死率、TTFT/TPOT、tokens/s、GPU 利用率/显存、进程重启次数。
9. **容量**：不得把 32 并发当永久上限；按真实 prompt 长度和输出长度重新确定。
10. **回滚**：停止新实例，恢复上一 commit/配置；健康检查失败不继续放量。

## 4. 放量/回滚阈值

- 5xx 或 engine error 连续 5 分钟 >2%：停止放量并排查。
- 进程不可用 >1 分钟：告警；>5 分钟：回滚。
- TTFT p95 >2s 或 TPOT p95 >100ms 持续 10 分钟：降低并发。
- GPU 显存 >95% 持续 5 分钟：禁止加并发，必要时降 `MAX_SEQS`。
- 单次 OOM/全批 `EngineStepError`：视为阻断放量事件。

## 5. 生产建议

- **32GB 可灰度；48GB 更适合正式业务**。当前实例不是容量承诺依据。
- **32GB + CUDA Graph 下 `MAX_SEQS=32` 实测 32 活跃并发 OOM**；灰度固定 24，
  32 客户端会排队（0 错误但 TTFT 升高）。
- V2-Lite bf16 权重约 29.3GB；FP8 KV 不减少权重显存。
- 仅支持 DeepSeek-V2/V2-Lite；不要接 V3/R1 请求。
- 公网 HTTPS、WAF、配额与审计属于对外上线前置项；当前配置为内网灰度。
