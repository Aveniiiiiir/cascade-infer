## 一、修复清单（按严重度）

### 高危（6 条）

| # | 缺陷 | 位置 | 根因与后果 | 修复 |
|---|---|---|---|---|
| H1 | 入队长度守卫用 `runtime_max_model_len`（含投机余量）而非 `max_model_len` | scheduler.py add_request | prompt ∈ [max, runtime) 时入队成功→prefill 完成→`allowed=0`→assert 崩溃→**fail_all_inflight 判死全部在途请求**（HTTP `len==max` 同样放行）；已可执行复现 | 守卫改 `> model.max_model_len`；server 层 `>=`；decode 循环加满长 FINISHED_LENGTH_CAPPED 封顶（恰好填满且无截断标志的边界） |
| H2 | `AsyncEngine.abort` 跨线程直调 scheduler，与引擎线程 step 无同步 | server.py | 竞态窗口：Sequence 断言崩溃→全批陪葬；block_table 迭代中并发 append→**新块被 abort 释放回池但仍挂在表内→下次分配复用→跨请求静默 KV 串写**（最坏：无任何报错）；已确定性复现崩溃交错 | abort 投递 `threading.Queue`，引擎线程每轮 step 前 drain 串行执行（与 add_request 同模式） |
| H3 | varlen+SO：`K_actual==0` 时 `masks[0]` 从未填充 | model_runner._verify_mtp_seq | 全零位掩码→logits 全 -inf→softmax **NaN**→`_inv_cdf` 全零行 ValueError→引擎级 fail_all_inflight；varlen+SO 每请求第一个 decode 步必触发 | 行 0（当前语法态）无条件填充；试探循环重构 |
| H4 | SO 试探循环无视 xgrammar `accept_token` 返回值 + 按固定 K 回滚 | model_runner + matcher.py | xgrammar 契约：False=非法且状态未推进。回滚超实际接受数抛 RuntimeError→fresh/SO+MTP 首步必炸；否则连带吃掉已提交 token→**语法状态永久 desync（静默输出错乱）**；经官方文档交叉验证 | accept_token 全链路返回 bool（含 stub）；False 即停止试探、掩码沿用行 j；`rollback(实际推进数)`；committed 接受也检查返回值 |
| H5 | `acceptance_full.sh` `sleep 30` 后直接 curl | scripts/ | 真实模型加载 ~400s→**脚本在真实模型上必失败**；失败路径残留服务进程 | 就绪探测（600s）+ trap 兜底清理 |
| H6 | README 虚报能力 4 处 | README.md | 声称支持 V3/R1（config 显式拒绝）、宣传 ZOS 三段式（引擎为同步序）、EP 多卡/FP8 KV（未实现）、快速开始用 HF repo id（loader 只收本地目录） | 全部更正为实际状态 |

### 中危（8 条）

| # | 缺陷 | 修复 |
|---|---|---|
| M1 | 引擎步异常回执被丢弃→在途客户端挂死 600s | `EngineStepError(receipts)` 携带判死回执；服务层 `_put` 它们 |
| M2 | `_put` setdefault 复活死键→断连后无界泄漏（每条 ro 携带全量输出拷贝，16k token≈GB 级） | 活跃 rid 集合：迟到输出丢弃+止损 abort；断连路径也对齐 abort |
| M3 | graph scratch 块对调度器容量不可见→池高估 1 块→满池请求活锁空转（复现：6/6 步空调度） | `BlockManager.reserved/capacity`；调度器容量守卫全部改用 capacity |
| M4 | varlen 集成断裂 6 处：(a) rates 永不回灌 (b) ENABLE_MTP_VARLEN 死变量 (c) 草案不截断→形状失配 (d) 前缀草案被丢弃 (e) fresh 行污染校准器 (f) plan 断言崩溃 | 全修：引擎回灌管线 + env 接线 + 前缀截断 + config 交叉校验 + 校准器门控；另修**冷启动死锁**（未知 rid 先验 [0.0]→v≡1 永不回灌→改乐观 [1.0]） |
| M5 | MTP 目标分布 top-p/top-k 截断后未归一化→接受比乘 1/Z→投机解码不分布保持 | `_verify_mtp_seq` 归一化后取 log（贪心 Z=1 不受影响） |
| M6 | SO staging 请求不可 abort（编译中最长 30s） | `LLMEngine.abort` 先 pop `_so_staging` |
| M7 | SO 编译 pending 期引擎 100% CPU 空转 | 空产出+pending→sleep 1ms（server 与 generate 两处） |
| M8 | `e_score_correction_bias` 构造在 bf16 默认 dtype 下→"保持 fp32"分支实为 no-op | 参数显式 `dtype=torch.float32` |

### 记录后置（2 条，不修）

- **COW 半实现**：`cow_copies` 有生产者无消费者——当前路径不可达（前缀缓存只 pin 满块、无 fork），一旦引入 fork 需先实现 KV 拷贝，否则静默损坏。已在调度器 docstring 标注。
- **Sampler 3 次 D2H 同步**（goldens/top-k/top-p `bool(any())`）：纯延迟（每采样步串行化 CPU/GPU），不影响正确性；重构需张量化条件，后置。
