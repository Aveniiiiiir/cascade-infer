# 推理优化落地：n-gram 投机解码 + FP8 KV Cache（2026-11-24）

## 1. 选型结论（检索依据）

- **无 draft 模型投机解码**：TensorRT-LLM 2026 已做 n-gram 自动启用；MLSys'26
  实测 draft-model SD 在部分模型上不如 n-gram。V2-Lite 没有 nextn 权重，
  这是唯一的零训练 SD 路径。
- **FP8 KV**：DeepSeek-V3 生产格式 = latent c FP8(e4m3) + rope bf16 +
  每 128 维一组 fp32 scale（656 B/token/层 vs bf16 1152 B）。
- 未采用：2–4bit KV（依赖专用反量化 kernel，naive 实现吞吐反降）、
  EAGLE-3/Medusa（需训练 draft head）、PD 分离（单卡无意义）。

## 2. P0：n-gram / prompt-lookup 投机解码

实现：

- `cascade/sampling/ngram_draft.py`：无状态最长后缀匹配（`bytes.rfind`，
  C 速度），匹配最近一次出现并取后续 token 作为草案。
- `cascade/sampling/mtp_verify.py`：新增**稀疏草案分布**路径
  （`draft_token_probs`）。n-gram 不分配 `[K, V]` logprobs；接受概率为
  `min(q[d], p_d)`（单点分布的精确 Σmin），拒绝残差只在 d 列减 α·p。
- 引擎：`CASCADE_NGRAM_DRAFT=1` 自动注入；复用 MTP 的验证 / 回滚 /
  SO 掩码 / 提交协议；未命中位置用 -1 哨兵强拒。
- **CUDA Graph 多 token 验证行**：`tokens_per_seq = 1+K`；新增
  `uniform_v` graph-safe prefill 路径，段元数据全部由 device 张量构造
  （`positions[::v] + v` 推导首位置）。整批 v 一致时走图；varlen /
  动态长度自动退化 eager。

## 3. P1：FP8 KV Cache

- 布局：`c` float8_e4m3 + `rope` bf16 + `scale` fp32 [每 128 维一组]；
  V2-Lite 656 B/token/层（1.76× 压缩）。
- 量化在 PyTorch 侧完成（图捕获安全）；Triton kernel 只搬运字节。
- decode / prefill 的 FP8 kernel 在 kernel 内 dequant 到 bf16 后走同一组
  `tl.dot`；显式路径 gather 用 int8 视图（CPU 的 fp8 高级索引未实现）。
- 开关：`--kv-cache-dtype fp8` 或 `CASCADE_KV_DTYPE=fp8`。

### 精度迭代记录

- 首版 **per-token 单 scale**：e2e teacher-forcing explicit
  627/640 = **0.9797 < 0.985**，未过门槛（分歧均为 HF margin ≤0.25 的
  tie 级）。
- 改为 **每 128 维分组 scale**（DeepSeek-V3 生产格式）后重跑 e2e：
  `FP8B_EXIT=0`，explicit/absorbed 双门槛通过（pytest 通过时 stdout 被
  capture，未打印具体百分比）。

## 5. 使用

```bash
# n-gram 投机解码（无需 draft 模型）
CASCADE_NGRAM_DRAFT=1 CASCADE_MODEL=/models/DeepSeek-V2-Lite bash scripts/serve.sh

# FP8 KV
CASCADE_KV_DTYPE=fp8 CASCADE_MODEL=/models/DeepSeek-V2-Lite bash scripts/serve.sh

# 组合
CASCADE_KV_DTYPE=fp8 CASCADE_NGRAM_DRAFT=1 bash scripts/serve.sh
```

`serve.sh` 现在自动解析 Python：`PYTHON` 环境变量 → `python` →
`/root/miniconda3/bin/python` → `python3`（修复非交互 SSH 下 PATH 缺失导致
`nohup: python: No such file or directory`）。
