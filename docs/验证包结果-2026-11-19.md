## 二、量化到的数值发现（本轮核心增量）

| 发现 | 数据 | 含义 |
|---|---|---|
| **explicit ↔ absorbed 互拍** | 188/192 = **97.92%**（分歧 4 处） | 两路径各自对 HF 均 98.96%，但彼此有独立分歧——数值上各自独立地"接近 HF"，非同源误差 |
| **absorbed decode split-K 路径** | 92/95 = **96.84%** | 增量逐 token（decode kernel）比整段（prefill kernel）低 ~2pp——kernel 数值路径差异首次量化 |
| **跨批形状敏感**（贪心） | 20 步一致后分叉 | bf16 tie 级噪声 + MoE 分桶/注意力分块形状依赖 → xfail 记录 |
| **跨批形状敏感**（温度 0.7） | 位置 3 分叉 | 温度放大 logits 批形状差 |
| **前缀缓存命中改变重放** | 同 seed 与 miss 跑分歧 | **新发现**：cache 命中改变 prefill 批形状（跳过已缓存段）→ 输出与 miss 跑不一致——跨形状敏感的又一致现；同形状重放不受影响 |
| **门控 bf16 vs fp32** | 新驱动持平 | 实测结论环境相关，代码保留 bf16 + 注释 |

## 三、本轮修复的真 bug（3 个，已提交）

| # | bug | 根因与修复 |
|---|---|---|
| 1 | **默认配置引擎构造期 OOM**（rope 预热） | KV 预算（free×0.9）吃光全部剩余显存后 rope cos/sin 构造（~420MB 峰值）才执行。修复：`_profile_num_blocks` 预留 rope 构造峰值（2×runtime×rope_dim×20B）+ 512MB 激活 headroom。此前所有真实模型测试都显式传 max_model_len，默认路径零覆盖 |
| 2 | **forward 阶段异常裸逃逸** | EngineStepError 只包裹采样阶段——prepare/forward 异常使 pending 悬空，离线 generate 后引擎状态损坏。修复：整个执行阶段统一包裹。由验证脚本 A 的崩溃注入暴露 |
| 3 | **批不变测试自身从未正确执行过** | 3 项测试历史上要么 skip 要么未跑到：req-键假设错误（KeyError）+ 跨形状期望过高。修复：values() 取值 + 跨形状 2 项 xfail（严格跟踪）+ 同 seed 重放保持硬门槛 |

另修：README「批不变」措辞精确化（确定性采样 + 同形状重放一致；跨形状 bit 级为 DeepInfer 级目标）。
